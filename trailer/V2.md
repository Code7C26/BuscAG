# BuscAG V2 — 60 segundos

Nuevo montaje independiente: **1920×1080, 30 FPS, H.264/AAC, sin narración**.
La V1 de 90 segundos permanece en `deliverables/BuscAG-trailer-draft.mp4`.
La V2 se exporta exclusivamente a `deliverables/BuscAG-trailer-v2.mp4`.

## Dirección y montaje

30 planos, con cortes sobre una grilla de 120 BPM (15 fotogramas por pulso).
Alterna tipografía a pantalla completa, objeto en perspectiva, interfaz ampliada,
tarjetas enfrentadas, recorrido de mapa y dos dispositivos. No usa la composición
repetida de párrafo a la izquierda e interfaz a la derecha.

| Tiempo | Imagen y acción | Música |
| --- | --- | --- |
| 0–5 | Mochila en penumbra; PERDISTE / ALGO; barrido de luz | Textura, subgrave y tensión |
| 5–12 | Logo en profundidad, comunidad en movimiento, tarjetas | Entrada del beat, bajo y sintetizador |
| 12–17 | PUBLICALO; escritura real de título y descripción | Percusión y arpegios |
| 17–24 | BUSCÁ; búsqueda escrita, filtros de zona y fecha | Pulso sostenido |
| 24–28,5 | Mapa: filtros, zoom y paneo; tres cortes rápidos | Hats y acentos |
| 28,5–32 | Dos tarjetas convergen; LAS PISTAS / SE CONECTAN | Subida; silencio de 31,5 a 32 |
| 32–38 | Drop: comparador auténtico; COINCIDENCIAS / AUTOMÁTICAS | Bajo, bombo, clap y lead completos |
| 38–46,5 | CONECTÁ; escritura, envío y respuesta; dos dispositivos | Groove y melodía |
| 46,5–51 | Contraparte confirma; estado Recuperado; RECUPERALO | Resolución y acentos |
| 51–53 | Regresa la mochila: VOLVIÓ | Preparación del cierre |
| 53–60 | Logo en profundidad; «Lo que se pierde, nos une.» | Impacto final y cola musical |

El detalle de los 30 planos, sus límites y tipos está en `v2/timeline.mjs`.

## Interfaz auténtica, demostración aislada

Los siete videos se capturan del cliente React/Vite del repositorio, compilado
localmente. Hay escritura, apertura de filtros, zoom/paneo Leaflet, comparación,
envío de chat y confirmación bilateral. No se redibujaron controles. Los usuarios,
objetos, imágenes, mensajes y respuestas del backend son ficticios. Ninguna sesión
se conecta al backend remoto. No se leen archivos .env ni credenciales del usuario.
La mochila perdida y encontrada coinciden por los datos de ensayo: el índice del
comparador no garantiza propiedad ni representa una nueva funcionalidad de IA.

La captura utiliza viewport 1600×900 y densidad 2 (3200×1800). Muestrea 15 imágenes
por segundo y las codifica a 30 FPS; las animaciones de Remotion son de 30 FPS.
Las pausas de las acciones se coordinan con los fotogramas capturados para que una
máquina lenta no comprima toda la interacción al comienzo del clip. La captura
puede variar ligeramente entre máquinas; los clips incluidos fijan el montaje.
El mapa utiliza geometría original ficticia y está identificado como ilustrativo.
La recuperación representa una solicitud del propietario a su contraparte y su
confirmación, no una recuperación arbitraria ni dos publicaciones cerradas a la vez.

## Música original

`v2/audio.mjs` sintetiza una pista estéreo de 48 kHz con bombo, clap, hats,
subgrave, bajo, arpegios, leads y risers. 120 BPM, progresión en Re menor.
No usa canciones, muestras externas, voces ni material de librerías.
Beat en 5 s, subida en 28 s, silencio de medio segundo y drop en 32 s.
La pista se genera localmente; no es necesario descargar audio ni pagar licencias
musicales. Los términos de los recursos originales están en `LICENSES.md`.

## Windows: previsualizar y exportar

Node.js 22 LTS/24, Chrome/Chromium y FFmpeg/ffprobe en PATH para recapturar y verificar.
No necesita Docker, Supabase CLI ni iniciar sesión en Firebase.

```powershell
cd trailer
npm.cmd ci
npx.cmd playwright install chromium
npm.cmd run audio:v2
npm.cmd run studio:v2
```

Abrir la URL local indicada por Studio y elegir `BuscAG-V2`. Los clips reales de
demostración ya están incluidos. No hay que volver a capturarlos para renderizar.

```powershell
# Con 4 GB de RAM: un solo proceso de render.
$env:BUSCAG_TRAILER_CONCURRENCY = "1"
npm.cmd run typecheck
npm.cmd run test:v2
npm.cmd run smoke:v2
npm.cmd run render:v2
npm.cmd run verify:v2
npm.cmd run sheet:v2
```

Resultado: `deliverables/BuscAG-trailer-v2.mp4` y `verification-v2.json`.
El render completo puede tardar varios minutos; evitar otras aplicaciones pesadas.
Si Remotion no encuentra Chrome, configurar `BUSCAG_TRAILER_BROWSER` con la ruta
absoluta a `chrome.exe`. No desactivar seguridad del navegador ni TLS.

Opcional, para regenerar recorridos después de cambiar la app:

```powershell
# Primero instalar dependencias del cliente si todavía no existen:
npm.cmd --prefix ../src/code ci
npm.cmd run capture:v2
npm.cmd run stills:v2
```

`capture:v2` inicia un servidor **local** temporal y lo cierra al terminar.
FFmpeg se puede indicar mediante `FFMPEG_PATH`; `verify:v2` necesita ffprobe en PATH.
`stills:v2` genera 17 imágenes en `out/v2`. Para revisar un plano aislado:
`npm.cmd run render:v2 -- --shot=recovery`.

## Comprobaciones

`test:v2` comprueba continuidad de los 30 planos, duración, cortes en la grilla,
fronteras narrativas, clips de interfaz, audio original y conservación de V1.
`verify:v2` inspecciona el MP4 realmente exportado: 1800 fotogramas, 1080p30,
60 segundos, H.264 y AAC estéreo. Decodifica el video completo y mide sonoridad/pico del audio AAC. Guarda hashes y metadatos sin datos personales.
La inspección visual se hace sobre fotogramas exportados y la auditiva sobre el
MP4; las comprobaciones de metadatos no certifican por sí solas la calidad musical.
Este tráiler no valida el funcionamiento remoto ni Web Push en dispositivos.
